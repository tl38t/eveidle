## 二、方法：一份内核，两个宿主

探针刻意设计成**宿主无关**，用两个完全不同的宿主跑同一份代码，以证明「微信端只需换宿主」：

```
                    canvas-ui-kernel.js  (492 行，只依赖 ctx + measureText)
                              │
        ┌─────────────────────┴─────────────────────┐
   宿主 A：Node 离屏 canvas                宿主 B：浏览器 canvas
   (@napi-rs/canvas)                      (Chrome，真实鼠标/触摸)
   → 产出 5 张 PNG 供肉眼核验              → 产出可点按的交互 demo (index.html)
        └─────────────────────┬─────────────────────┘
                              │
                    微信端 = 宿主 C：
        wx.createCanvas().getContext("2d") + wx.onTouchStart/Move/End
```

**严格纪律（不手写 mock）**：

- 页面数据来自**真实逻辑层** —— 在 `vm` 沙箱里按 `index.html` 顺序加载 **108/108** 个逻辑脚本（复用 P1 已验证的最小 DOM shim）；
- 显示状态来自**真实** `getSettingsDisplayState(gameState)`；
- 文案来自**真实** `I18N.t(key)`，语言切换走**真实** `I18N.setLocale()` + 真实 `catalog-*.js`；
- 版本号来自真实的 `tools/build-version.json` 复刻，更新日志来自**真实** `window.GAME_CHANGELOG`（V0.9.2）。

### 4.2 i18n 覆盖率（⚠️ 重要发现）

用「记账版 `t()`」抓出设置页实际用到的 **40 个 i18n key**，回真实 catalog 查：

| 语言 | 命中 | 缺失 |
|---|---|---|
| en-US | **13 / 40（32.5%）** | 27 |
| zh-TW | **13 / 40（32.5%）** | 27 |

缺失样例：`默认跟随系统语言（Steam 版跟随客户端语言）…`、`功能`、`本次更新内容 · V…`、以及**全部更新日志条目**。

**根因（既有缺陷，非迁移引入）**：

1. **文案漂移** —— `index.html` 里「界面语言」的说明已改写成新版本，但 `catalog-*.js` 里还是旧版 `可手动选择；Steam 语言联动将在 Steamworks 接口接入后启用。` ⇒ **英文/繁中玩家现在已经会看到中文残留**。
2. 更新日志是运行时拼 `innerHTML` 注入的，`MutationObserver` 只能靠「子串替换」兜底，而 `translateFromCatalog` 有「替换后仍残留汉字则整段回退」的规则 ⇒ 更新日志条目**结构性无法翻译**。

## 五、关键发现

### F1 ⭐ 「数据→视图模型」这一层**已经做好了**（最大利好）

项目已经有 **45 个 `get*DisplayState(state)` 纯函数**，把 `gameState` 投影成视图模型；渲染函数只负责「视图模型 → HTML 字符串」。

| 文件 | `DisplayState()` 调用 |
|---|---|
| `shell-render.js` | **36** |
| `manufacturing-render.js` | 9 |
| `station-render.js` | 5 |
| `combat-render.js` | 3 |
| `booster-render.js` | 2 |

⇒ **Canvas 端只需要替换最后一步**（视图模型 → 像素），前两步（业务逻辑、投影）**一行都不用动**。这是本次探针最重要的结论，它把 U3 的成本从「重写 1.8 万行」压到「重写渲染层」。

### F2 ⚠️ 但 legion / alliance / wormhole **没有投影层**（成本热点）

| 文件 | `DisplayState()` 调用 | 实际取数方式 |
|---|---|---|
| `legion-render.js`（922 行） | **0** | 直接读 `gameState` |
| `alliance-render.js`（753 行） | **0** | `gameState.alliance` ×6、`gameState.equipment` ×5 |
| `wormhole-render.js`（515 行） | **0** | 直接读 `gameState` |

⇒ 迁这三页**必须先补投影层**，否则 UI 会跟逻辑层耦合（也就拿到不「一份逻辑、三端复用」的收益）。

### F3 🔴 Font Awesome 在 Canvas 上**全部不可用**

393 处图标使用、87 个不重复图标，在 Canvas 里**一个都渲染不出来**（探针里 `🔧` 直接变成方框 □）。三条可选路：

| 方案 | 代价 | 评价 |
|---|---|---|
| 矢量绘制 | 87 个图标逐个画 | 最干净、零包体，但 87 个是硬工作量 |
| 图标字体 | `wx.loadFont()` 加载，1 个 ttf | 折中，需验证小游戏对自定义字体的支持 |
| 图片图集 | 一张 sprite + 裁切 | 最稳，但**增加包体**（主包只有 0.99MB 余量） |

### F4 🔴 CSS 6,501 行里能「白拿」的部分为 **0**

`:hover`、`@media` 断点、`transition`、`flex-wrap`、`overflow` —— Canvas 全都没有。探针里已经实感到：

- 下拉、开关的**过渡动画**要自己插值；
- `@media (max-width: 520px)` 要写成条件分支；
- `flex` 只实现了 `col/row + gap + align + flex` 子集，**没有 `flex-wrap`**；
- 滚动要自己裁剪 + 处理惯性。

### F5 ⚠️ CJK 换行必须自实现（一次性成本）

Canvas **没有自动换行**，`measureText` 只是单行测量。内核用 28 行实现了「CJK 逐字可断 + 拉丁成词整体断 + 超宽回退」，**全站每页都要用**，属一次性投入而非每页成本。

### F6 ⚠️ 探针踩到的 shim 缺口（要回补到 P1 的 shim）

P1 的最小 DOM shim **不够**：`I18N.setLocale()` → `applyNav()` → 遍历 `document.body` 并调 `getAttribute()` ⇒ 报 `TypeError: element.getAttribute is not a function`。

⇒ **P2/P3 与 P1 的 shim 必须合并成同一份**（补 `getAttribute/setAttribute`、把 body 做成「像元素」的对象），否则微信端一调 `setLocale` 就崩。

### F7 ✅ 内核真的平台无关

同一份 `canvas-ui-kernel.js` + `page-settings.js` 在 **Node 离屏 canvas** 与 **浏览器 canvas** 上渲染结果一致 ⇒ 微信端只剩两个适配点：`wx.createCanvas()` 与 `wx.onTouchStart/Move/End`。

### F8 交互必须全部手写

探针里实现的：点按命中（**逆序命中测试**，后绘制的在上）、浮层遮挡（浮层打开时吞掉下层点击）、滚动裁剪、拖动 vs 点按的判定（位移 > 6px 视为拖动）。真实端还要加：**长按、双击、惯性滚动、点击态反馈**。

## 六、对 D1（UI 迁移路线）的影响

**建议：D1-B 自研 Canvas 内核**，理由与备选对比：

| 方案 | 收益 | 代价 | 判断 |
|---|---|---|---|
| **A. 官方 `minigame-canvas-engine`** | 不写布局内核 | 264 处 `innerHTML` 模板要改写成它的模板语法；控件要自建；只有 Flex 子集 | ⚠️ 省了内核（492 行），但模板迁移成本远超 |
| **B. 自研内核（本探针已证）** | 表达力不受限；**可复用 45 个投影函数与 i18n**；内核仅 492 行 | 控件库要自己养（开关/下拉/列表/进度条/标签页/模态/提示） | ✅ **推荐** |
| **C. 逐页 Canvas 重写（不用内核）** | 无 | 每页重复实现布局/换行/命中 ⇒ 122 个 render 函数各自为政 | ❌ 淘汰 |

配套建议：
- **S1 阶段只做 3–4 个核心页**（类目审核只需要证明品类，不需要全站）；
- 迁 legion/alliance/wormhole 前**先补 `get*DisplayState` 投影层**（F2）；
- 迁微信前**先补 i18n 缺口**（F5/4.2）—— 这顺带修好 Steam/TapTap 现存的英文残留。

## 九、复现方式

